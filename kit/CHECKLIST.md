# 확장 프로그램 스토어 제출 체크리스트

확장 하나를 올릴 때마다 위에서부터 따라가면 됩니다. 처음 한 번만 하는 일은 맨 앞에 있습니다.

## 0. 처음 한 번만

- [ ] 개발자용 Google 계정 준비 (YouTube·Gmail 등에 쓰는 메인 계정과 분리 권장)
- [ ] 그 계정에 2단계 인증 켜기
- [ ] [Chrome 웹 스토어 개발자 대시보드](https://chrome.google.com/webstore/devconsole) 가입, 등록비 US$5 결제 (한 번만)
- [ ] 판매자(trader) 여부 신고: 무료 개인 프로젝트면 비판매자
- [ ] `release.config.json` 의 `developer`, `contactEmail`, `domain` 채우기
- [ ] Firebase Hosting 연결 (main에 push하면 GitHub Actions가 `dist/site/` 를 배포)
- [ ] (선택) 대시보드에서 도메인 소유 확인 → 등록정보에 공식 URL 표시

기본 게시 한도는 개발자당 2개입니다. 세 번째부터는 대시보드에서 증설을 요청하세요.

## 1. 새 확장 시작

- [ ] `node kit/scripts/new-extension.mjs <폴더> "<이름>"`
- [ ] 아이콘 교체: `extensions/<폴더>/icons/` (16, 32, 48, 128)
- [ ] `manifest.json` 의 `description`: 132자 이내, 스토어 요약으로 그대로 쓰임

## 2. 코드 점검

- [ ] 권한은 꼭 필요한 것만. `tabs`, `cookies`, `webRequest`, `history`, 넓은 호스트 권한은 심사를 길게 만듦
- [ ] 호스트 권한은 필요한 도메인 하나로 좁히기 (`<all_urls>` 피하기)
- [ ] 외부 스크립트 불러오기, `eval`, 인라인 스크립트, `onclick` 속성 없음 (원격 코드 금지, MV3 CSP)
- [ ] 사용자 데이터를 다루면 화면에 "저장된 데이터 지우기" 제공
- [ ] 사용자가 누르지 않았는데 스스로 다른 사이트에서 동작하는 기능 없음
- [ ] 다른 서비스 화면을 자동으로 조작하는 기능이 있으면: 사용자가 직접 시작, 실행 전 미리 보기, 사람 속도의 간격

## 3. 사이트 페이지 (`site/<폴더>/`)

- [ ] `index.html`: 소개, 기능, 개인정보 요약
- [ ] `privacy.html`: 처리하는 정보, 저장 위치·기간, 통신하는 곳, 권한 이유, 지우는 방법, **Limited Use 문구**, 문의처, 시행일
      (스토어 정책: 브라우저 안에서만 처리하는 정보도 공개 대상이고, 사용자 정보를 다루면 방침 페이지가 필수)
- [ ] `support.html`: 사용법, 자주 묻는 질문, 문의
- [ ] `screenshot-1.png`, `icon.png` 넣기
- [ ] `npm run build` 로 미리 확인 → main에 push → https://util.cokeys90.dev/<폴더>/ 가 열리는지 확인

## 4. 스토어 등록 자료 (`store/<폴더>/`)

- [ ] `listing.md` 채우기: 상세 설명, 카테고리, 단일 목적, 권한별 사용 이유, 원격 코드 여부, 데이터 사용 항목
- [ ] 스크린샷 1280×800, 1~5장 (공개 이미지이므로 실제 계정·남의 로고 대신 예시 데이터 사용)
- [ ] (선택) 작은 홍보 타일 440×280

## 5. 패키징과 제출

- [ ] `node kit/scripts/pack.mjs <폴더>` (업데이트면 `--bump patch` 등) → 경고가 없을 때까지 고치기
- [ ] 개발자 모드로 `extensions/<폴더>/` 를 불러와 처음부터 끝까지 한 번 직접 써보기
- [ ] 대시보드 → 새 항목 → `dist/<폴더>-<버전>.zip` 업로드 (업로드 시 설치 자동 검사)
- [ ] 스토어 등록정보 탭: `listing.md` 의 문구와 이미지
- [ ] 개인정보 보호 탭: 단일 목적, 권한 이유, 원격 코드, 데이터 사용, 방침 URL
- [ ] 배포 탭: 처음에는 미등록(Unlisted) + 필요한 지역만
- [ ] 심사 제출. 보통 며칠, 길면 몇 주. 3주 넘으면 지원팀 문의

## 6. 게시 후

- [ ] `release.config.json` 의 `storeUrl` 채우고 `build-site.mjs` 다시 실행 → 사이트의 설치 버튼 활성화
- [ ] 업데이트할 때마다 `pack.mjs --bump` → 업로드 → 다시 심사
- [ ] 정보 처리 방식이 바뀌면 개인정보처리방침의 내용과 시행일 함께 수정
